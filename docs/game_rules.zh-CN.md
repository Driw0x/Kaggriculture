# Kaggriculture 游戏规则

本文件包含在开发Kaggriculture代理过程中作为参考所使用的游戏机制和规则。

这些规则基于官方Kaggriculture竞赛文档。

> 本文件仅用于开发参考，官方竞赛文档仍是权威来源。

<a id="kaggriculture"></a>
# Kaggriculture

一个农场模拟游戏，两名玩家通过向动态市场销售农产品来竞争，以最大化收入。

<a id="overview"></a>
## 概述

每位玩家初始拥有一个空农场和少量初始资金（即种子资金）。每回合，玩家可以执行诸如在地图上移动、购买种子或牲畜、播种、浇水、收获农产品或动物产品，以及在市场出售这些产品等操作。游戏持续固定时间，代表一个季节，最终谁拥有银行中最多资金，谁就获胜。

对于作物，'产量/每块地/每天'是指在每日浇水并于峰值产量时收获的情况下，总收获单位数除以地块被占用的天数。对于动物，这是首次获得产量后达到的稳态生产率（`1 / interval`）；动物在被喂养期间持续生产，因此没有固定的占用时间需要相除。动物的'最大产量'是`max_held`，指的是未收获产品在地块上堆积的上限，而不是生命周期内的总产量。

作物的“达到最大产量所需时间”是指每日浇水时产量停止增长的生长日龄，并不总是增产期结束的时间：

- **Melon** 的增产期为生长第 6—12 天，但基础产量为 1，每个浇水日增加 1 单位，于第 10 天达到 6 单位上限，因此第 11—12 天不再增加产量。施肥时在第 8 天达到上限。
- **小麦**和**胡萝卜**只有施肥后才能达到表列的最大产量 6 和 4；仅浇水时，峰值分别为 4 和 3。
- **番茄**和**草莓**持续产出，但*并非*无限期：最多按计划产出 4 次，番茄在第 8—11 天，草莓在第 10、12、14、16 天；此后植物衰减并变为杂草。

所有植物都须每日浇水，连续两天未浇水就会变为杂草。所有动物都须每日用小麦喂养，连续两天未喂养就会逃走且无法找回。小麦也可按当前市场价格购买。

<a id="actions"></a>
## 操作

玩家每回合可执行一项操作。每天 24 回合，一季 30 天，共 720 回合。

<a id="farmer--farm-hand-action"></a>
### 农民 / 雇工操作

每名农民或雇工每回合都可获得一项操作。农民和雇工**可以**占据同一格。

<a id="movement"></a>
#### 移动

- 北、南、东、西 — 沿该方向移动一个格子。超出棋盘边缘的移动无效。锁定格子是可通行的：单位可以移动到并穿过未购买的区域，但格子上的操作（`PLANT`、`WATER`、`BUILD_*` 等）在锁定格子上均无效且不消耗任何资源。例外是进入储物间的操作 `PICKUP`、`DROP` 和 `PLACE`-into-shed，这些操作可以从任何可访问储物间的格子执行，即使该格子被锁定——它们仅将该格子作为站立位置使用，而不会改变该格子本身。

<a id="shed"></a>
#### 储物间

从储物间拾取一个物品（必须正交相邻）到库存中

- PICKUP `<item>` `[n]` — 将储藏室中最多 `n` 个 `<item>`（默认 1 个）移入当前农民或雇工的背包。可拾取储藏室中存在的任何物品，例如动物、肥料及收获的农产品。种子存放在独立槽位中，永远不会被拾取；`PLANT` 直接消耗种子。
- DROP — 与储物间正交相邻时，将当前农民/手的全部库存倾倒到储物间中。超出 `shedCapacity` 的部分被丢弃。如果不与储物间相邻，则无效。

<a id="plants"></a>
#### 种植

- PLANT — 种植从市场购买的种子
  - 所有农民/农工均自动拥有种子
  - 如果在特定回合尝试种植过多，将不种植任何种子
    - 例如，如果你有 1 粒西瓜种子，但有两个单位执行 PLANT MELON 命令
- 水 — 为植物浇水。这只需要每天进行一次，同一天内的后续浇水操作将不生效。
- 收获 — 从植物上采集作物。如果植物没有后续产量，则会从地图上移除。每次收获操作至少会获得一个单位的作物，额外产量取决于浇水和施肥（具体公式因作物类型而异——见下方收获产量部分）。收获的物品将被添加到库存中。
- 施肥 — 为植物施肥以提高其潜在产量（见下方收获产量部分）。
  - 连续三天每天的每日产量奖励翻倍。该奖励仅在植物当天也接受了浇水的情况下生效（基本需求优先）。

<a id="animals"></a>
#### 动物

- 放置 `<item>` `[n]` — 从当前农民/手部库存中将物品丢到某个方格或棚舍中：
  - **动物放置**：站在匹配的空结构上（在鸡舍为 `GOOSE`，在牧场为 `SHEEP`/`COW`）时，会将一个动物从库存中放置到该方格上。`n` 参数被忽略。
  - **棚舍丢弃**：站在棚舍正交相邻的位置时，最多可将 `n`（默认值为1）个 `<item>` 从库存中移动到棚舍中。数量上限为 `shedCapacity`；超出部分仍保留在库存中。
- 喂食 — 使用小麦喂养动物（每天只需进行一次）
- 收获 — 收集动物所产的蛋、奶或毛。
- 收集肥料 — 从动物身上收集1单位肥料。每只存活的动物每天末都会产生1单位肥料，无论是否被喂食或照料。未被收集的肥料不会累积，因此一只动物被遗弃五天后仍只产生1单位肥料。
- 照料 — 照料动物（每天一次，若已照料则操作无效）。见下方动物照料部分。

<a id="animal-care"></a>
#### 动物照料

照料会积累一个产量奖励，该奖励将在动物下一次生产时发放：

* 在每日结束时，如果动物当天既被喂食又接受了照料，则 `pending_care_bonus` 增加1。若动物当天未被喂食，则不会积累奖励（基本需求优先）。
* 在预定生产日，如果动物被喂食，则整个积累的奖励将被添加到该次生产的产量中（在基础1单位之上），并重置为0。
* 如果动物在生产日未被喂食，则仍会产生基础1单位产量，但不会应用积累的奖励，且奖励将重置为0。
* `pending_care_bonus` 会间接受到每只动物 `max_held` 限制的约束，限制在 `yield_units` 上。

<a id="terrain"></a>
#### 地形

- 建造鸡舍 \- 在未被占用的方格上添加一个鸡舍
- 建造牧场 \- 在未被占用的方格上添加一个牧场
- 挖掘 — 从方格中移除植物以释放空间，或移除杂草（不会产生任何作物），或移除一个**空置**的鹅舍/牧场。如果鸡舍或牧场上有动物，则无法进行挖掘操作；该操作将无效。

<a id="other"></a>
#### 其他

- 通行 — 如果没有任何操作可执行，则默认执行此操作（可选）

<a id="market-action"></a>
### 市场操作

每回合你可以提交最多 `maxMarketOrdersPerTurn`（默认为10）条市场操作；超出该限制的订单将被静默丢弃。这是一个有序列表，当双方都有订单时，市场订单将按顺序同时处理（每方各一条）。

- BUY\_SEED — 从市场购买 N 个单一物品。
  - BUY\_SEED WHEAT 1
- BUY\_ANIMAL \-
  - BUY\_ANIMAL GOOSE 1
- BUY\_PRODUCT
  - BUY\_PRODUCT WHEAT 1
  - BUY\_PRODUCT FERTILIZER 1
- SELL — 向市场出售 N 个单一物品。
  - SELL WHEAT 1
- HIRE — 每日雇佣一名农工。同一天雇佣的农工数量越多，成本越高。
- BUY\_LAND \- 解锁一片新的 5x5 土地区域用于耕种。成本逐渐增加。
  - 成本为：$1k, $2k，$4k

<a id="watering--animal-feed"></a>
## 浇水 / 动物饲料

植物（和动物）必须每隔一天至少进行一次浇水/喂食。浇水每天只需进行一次，后续的浇水操作将无效。如果植物连续两天未被浇水，则在当天结束时会变成杂草。如果动物未被喂食，则会逃脱（无法收回）。

新种子从 `consecutive_unwatered = 1` 开始——种植当天本身即算作第一次遗漏日。如果当天种植且未浇水的种子，在当天结束刷新时会达到 2，随后在当晚变成杂草，而不会继续生长。新种植的植物没有宽限期。

新放置的动物从 `consecutive_unfed = 0` 开始，因此它能在第一天未被喂食的情况下存活。

请注意，在一次收获作物的收获窗口期间进行浇水，会提升产量。这一点不适用于持续收获的作物/动物。详情见下文。

<a id="harvest-yields"></a>
## 收获产量

植物的产量可能根据其护理情况而有所不同。

* **一次性作物**（小麦、胡萝卜、甜瓜）：从植物 `max_yield_day`（最大产量所需时间）的一半开始（向上取整），在奖励窗口期间浇水，每天可增加一单位可收获产量。
  * 施肥的植物每天增加 2 单位。
* **持续性作物**（番茄、草莓）：按固定周期进行生产。基础产量为每次生产周期 1 单位。如果植物当天被施肥且浇水，产量将翻倍至 2 单位。
* 一旦植物达到其最大寿命，其可收获的总产量将每两回合减少 1，直到降至 0，此时该植物将变为杂草。
  * **一次性作物**在 `max_yield_day` 之后的一天达到最大寿命。
  * **持续性作物**在累计产量达到 `max_yield`（即已触发足够多的生产周期，无论是否已收获）之后开始衰减。

<a id="map-features"></a>
## 地图特征

每位玩家拥有自己的农场，农场由固定数量的格子组成。玩家无法看到对方的储物间状态，但可以查看对方农场的状态。

<a id="farm-space"></a>
### 农场空间

- 你农场附近的土地是一个 `boardSize` × `boardSize` 的网格（默认为 10×10），被划分为四个 5×5 的区域。最初，你的农场覆盖一个区域（占网格的 25%）。随着费用逐渐增加，你可以购买相邻区域，最终覆盖全部网格的 100%。
- 每种植物或动物占据农场上的一个格子。
- 玩家可以自由分配这些格子用于作物或牲畜，每种类型没有具体数量限制。
- 杂草有可能在农场的任意空格上生成，必须在土地被用于其他用途前清除。
- 农场上的格子可以是植物、鸡舍/牧场、杂草或空置状态。

<a id="shed-inventory"></a>
### 棚（库存）

- 作为收获后未售出物品或尚未播种种子的库存空间
- 每天开始时，农民和雇佣的农工会在棚内生成
- 每天结束时，农民和雇佣农工会将他们的库存丢入棚中（如果空间允许）
- 最多可容纳 100 个物品，不包括种子。一旦棚满，通过 `PLACE` 在白天中途或每日结束时添加的任何额外物品都将被丢弃——没有溢出储存区，因此农民或农工的库存中积压物品无法绕过容量限制。

棚位于棋盘中心，不是一个格子——它不会出现在 `tiles` 数组中，该数组仅包含 `None`、`"LOCKED"` 和结构字典。‘与棚正交相邻’指的是站在四个中心格子之一上，即 `(half-1, half-1)`、`(half, half-1)`、`(half-1, half)`、`(half, half)`（对于 `half = boardSize // 2`）。在默认的 `boardSize = 10` 下，这四个格子分别是 `(4,4)`、`(5,4)`、`(4,5)` 和 `(5,5)`，每个区域一个。由于只有 NW 区域初始解锁，其余三个格子初始处于锁定状态；但无论从哪个格子出发，都可以到达棚，因为棚本身从未被锁定。

<a id="farmerfarm-hand"></a>
### 农民/农工

<a id="hiring"></a>
#### 招聘

- 招聘是一种市场订单（`HIRE`）。每次想要雇佣额外一名农工时，费用都会增加。每天结束时，所有农工都会将库存物品留在农场并消失（需要每天重新招聘）
- 费用为`farmHandCostMult * fib(n)`，其中`n`是当天已雇佣的农工数量（斐波那契数列从1, 1, 2, 3, 5, 8, 13, ...开始）
  - 默认的`farmHandCostMult = 1`：1, 1, 2, 3, 5, 8, 13, 21等…（每天开始时重置）
- 雇佣的农工会出现在谷仓正交相邻的空位上，按照NWSE顺序排列。如果不存在空位，则选择占用人数最少的空位，若存在并列情况，则优先选择NWSE方向的空位
- 生成位置会忽略该格子是否被锁定。由于主农民初始位于`(4,4)`，最少占用规则会使每天的第一名农工被分配到`(5,4)`，该位置在东北象限被购买前是被锁定的。被锁定的格子是可通行的，因此在被锁定格子上生成的农工可以移动回未锁定的土地上

<a id="inventory"></a>
#### 库存

- 在收获或拾取物品时，这些物品会被添加到库存中
- 可以将物品放入谷仓
- 每天结束时，所有库存中的所有物品都会被添加到谷仓库存中（如果空间允许）。无法容纳的物品将被丢弃——超出部分将丢失

<a id="town-buildings"></a>
### 城镇建筑

随着赛季的推进，新的商店会以固定间隔（每 `townShopUnlockInterval` 天，默认为 3 天）解锁。每次解锁都会从完整的商店列表中均匀随机抽取（带替换），因此同一个商店可能会多次解锁——一个赛季最终可能有三家面包店而没有毛线店。一旦商店被解锁，它将在整个游戏过程中保持活跃，且最多解锁 8 次。总需求随着更多商店的解锁而单调增长。

每个解锁的商店实例会每 `townShopSellInterval` 轮（默认为 4 轮）消耗它所需求的每种产品一次。因此，在默认间隔下，一个需求小麦的商店每天会从市场中移除 6 单位小麦，两个这样的商店则会移除 12 单位。单一产品商店的消耗量为 2 倍。

此外，镇中心每 `townCenterSellInterval` 轮（默认为 24 轮，即每天一次）会消耗每种产品（不包括肥料）一次。这一消耗速率在整个赛季内保持不变，不会随时间增加。

|商店类型|增加需求的产品|
| :---- | :---- |
|面包店|鸡蛋、小麦|
|披萨店|牛奶、番茄、小麦|
|早餐小馆|鸡蛋、小麦、草莓|
|毛线店|羊毛（2 倍）|
|冰淇淋店|草莓，牛奶，小麦|
|宠物咖啡馆|胡萝卜（2个）|
|果汁店|草莓，牛奶|
|农民市场|小麦，胡萝卜，西红柿，草莓|

<a id="market-mechanics"></a>
## 市场机制

市场提供无限数量的种子和动物，价格固定。然而，售价会根据资源动态变化，并在不同日期间保持一致。

每种产品（以及肥料）在游戏开始时都拥有`I0 = 10,000`单位的市场库存，远超任何单个游戏实际生产量，因此库存几乎可以保证始终为正。产品的售价为`base`，价格为`I0`，当库存减少（玩家购买或城镇消耗导致供应下降）时价格上升，当库存增加（玩家出售）时价格下降。

<a id="selling-inventory-to-the-market"></a>
### 向市场出售库存

玩家可以在市场操作列表中排队任意数量的买卖订单（任意数量）。订单会并行处理，每次处理一个单位。例如，当两位玩家同时提交`SELL CARROT 10`订单时，我们首先使用当前胡萝卜价格，分别给两位玩家的首个胡萝卜定价，然后将2个胡萝卜加入市场（每个玩家各1个）——这可能会导致价格变动——并重复此过程，直到所有订单完成。

如果售价已降至`$1`（价格下限），该单位仍会被购买，但不会被加入市场库存，因此下限仍能对后续购买做出响应。

<a id="buying-inventory-from-the-market"></a>
### 从市场购买库存

只有 `WHEAT` 和 `FERTILIZER` 可以通过 `BUY_PRODUCT` 在市场上购买（其他产品虽然在市场可以出售，但不会被回购）。出售是无限制的：所有产品，包括从动物收集到的肥料，都可以通过 `SELL` 出售。导致市场库存减少的有两个因素：城镇建筑（城镇中心和商店，这些建筑免费消耗产品）以及玩家的 `BUY_PRODUCT` 订单。购买订单遵循与销售订单相同的逐单位并发处理流程。如果玩家在订单执行过程中资金耗尽，该订单将被终止。

买入价格以买入后的库存为基准报价，卖出价格以卖出前的库存为基准报价，因此，如果立即买入某商品再以相同商品立即卖出，且市场其他条件不变，最终净收益恰好为零。

<a id="the-price-function"></a>
### 价格函数

对于每种资源，曲线由一个基础价格、一个锚定通量 `T`，以及在均衡两侧各自独立的**形状函数**+**目标变动**来定义：

```
price(inv) = base + sign · amp · f(|inv − I0|)
  sign = +1  if inv < I0   (scarcity → price up)
  sign = −1  if inv > I0   (glut    → price down)
  amp  = target · base / f(T)        (derived; not stored)
  f    ∈ { linear, sq, sqrt, log, log10, hinge }   (log uses ln(1+x), so f(0)=0)
```

向下取整至 `$1`，并四舍五入到最接近的美元。

`hinge` 是唯一一个依赖于 `T` 而非仅依赖于 `x` 的形状函数：当 `u = x / T` 存在时，其值为 `u + 8 · max(0, u − 1)²`。当低于 `T` 时，其在 `u` 上呈线性关系；当高于 `T` 时，二次项开始主导，价格急剧上升。由于 `f(T) = 1` 由构造决定，因此 `target` 保持其原有的含义。

`T` 是一个 5×5 场地在最优灌溉条件下、无肥料情况下，在 24 天窗口内的生产容量（动物总产量在计算前已按 30% 折扣，以考虑小麦饲料的开销，并允许一天时间用于建造鸡舍或牧场）。24 天窗口是一个校准周期，而非 30 天的季节长度。它被有意设计得更短：初期几天设置密集，产量很低。

`target` 表示‘移动 `T` 个单位越过 `I0` 会使得价格变动 `target × base`’。在每侧选择不同的 `f` 和 `target`，使得具有相似生产特征的资源在战略上表现截然不同——小麦在短缺时恐慌，但在过剩时能吸收；甜瓜对短缺几乎无反应，但一旦过剩就会剧烈下跌；羊毛在规模上与甜瓜相似。高端资源（基础价格 > $100: strawberry, melon, milk, wool) use `above_target > 1`, so even modest gluts drive them straight to the $1）中，捆绑销售和销售时机的安排比普通主粮资源更为重要。

胡萝卜、番茄和鸡蛋在短缺侧使用 `hinge`，因此在正常需求下其价格保持在基础价格附近，一旦需求超过 `T`，价格将急剧上升。消耗这些产品的城镇商店列在 `unlocked_shops` 中。

- **胡萝卜** — 基础价格为 `hinge`，当需求达到 `below_target` 1.00 时。被宠物咖啡馆（单产品类型，因此每个消费量为双倍）和农民市场消耗。
- **番茄** — `hinge` 在 `below_target` 0.40。被披萨店和农场市场消费。
- **鸡蛋** — `hinge` 在 `below_target` 0.40。被面包店和早餐场所消费。

番茄和鸡蛋保留了 `below_target` 的 `linear` 曲线所替代的部分。因为 `linear` 的振幅已经归一化到 `x / T`，而这恰好是 `hinge` 的膝下分支，因此从 `I0` 到 `I0 − T` 的价格保持不变；曲线仅在膝部之后有所不同。

|资源|基础|I0|T|低于函数|低于目标|高于函数|高于目标|P(I0−T)|P(I0+T)|P(I0+2T)|
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
|**小麦**| 25 | 10,000 | 400 |sqrt| 0.80 |log| 0.20 | $45 | $20 | $19 |
|**胡萝卜**| 35 | 10,000 | 450 |hinge| 1.00 |sqrt| 0.70 | $70 | $10 | $1 |
|**番茄**| 60 | 10,000 | 200 |hinge| 0.40 |sqrt| 0.60 | $84 | $24 | $9 |
|**草莓**| 120 | 10,000 | 100 |sqrt| 0.70 |linear| 1.60 | $204 | $1 | $1 |
|**西瓜**| 250 | 10,000 | 300 |log| 0.20 |sq| 3.60 | $300 | $1 | $1 |
|**鸡蛋**| 50 | 10,000 | 332 |hinge| 0.40 |log| 0.20 | $70 | $40 | $39 |
|**牛奶**| 160 | 10,000 | 122 |sqrt| 0.60 |linear| 1.60 | $256 | $1 | $1 |
|**羊毛**| 200 | 10,000 | 105 |log| 0.20 |sq| 3.20 | $240 | $1 | $1 |
|**肥料**| 100 | 10,000 | 200 |linear| 0.40 |linear| 0.40 | $140 | $60 | $20 |

默认值位于 `MARKET_PARAMS` 中的 `kaggriculture.py`。通过在创建回合时使用 `env.configuration["marketParams"]` 提供资源级别的覆盖（稀疏：`base`、`I0`、`T`、`below_func`、`below_target`、`above_func`、`above_target` 的任意子集），无需修改代码，例如 `{"WOOL": {"above_target": 0.95}}`。

<a id="turn-processing-order"></a>
## 处理顺序

1. **动作验证** — 验证动作的合法性
2. **玩家动作** — 记录每个玩家采取的动作（同时发生）
3. **市场动作** \- 按上述描述的顺序处理市场队列
4. **城镇购买动作** \- 城镇中心和商店减少库存
5. **更新观察**
   - **每日刷新** — 如果适用，更新植物和动物在新的一天的状态，并将它们的喂养/浇水状态重置为 false
   - **市场刷新** — 根据上一轮的销售数据调整市场商品价格
   - **收入更新** — 根据任何购买或销售行为更新玩家的银行余额
   - **农场更新** — 清除已收获的植物，使用或出售的库存物品，添加新的植物/动物到农场等

<a id="win-conditions"></a>
## 胜利条件

胜利条件很简单——谁在赛季结束时拥有最多的硬币，谁就是赢家。也有可能两名玩家会平局。

<a id="reward"></a>
## 奖励

游戏结束时银行余额最多的玩家获胜。库存中未售出的物品不计入该总额。

<a id="observation-format"></a>
## 观察格式

传递给每个代理的顶层观察内容：

```py
{
  "player": int,           # 0 or 1
  "day":    int,           # 0-indexed in-game day
  "hour":   int,           # 0-indexed turn within the day
  "farms":  [farm, farm],  # public per-player state, indexed by player id (shared)
  "market": {              # shared
    "inventory": { "WHEAT": int, "CARROT": int, ... },
    "prices":    { "WHEAT": int, "CARROT": int, ... },
  },
  "town": {                # shared
    "unlocked_shops": ["BAKERY", "BAKERY", ...],   # may repeat; each entry consumes independently
  },
  "private": {             # this player only; opponent's private state is not visible
    "shed":        { "WHEAT": int, "GOOSE": int, "FERTILIZER": int, ... },
    "seeds":       { "WHEAT": int, "CARROT": int, ... },
    "inventories": [farmer_inv, hand_inv, ...],  # [0] is the main farmer
  },
}
```

每个 `farm` 字典（公开，两个玩家均可看到）：

```py
{
  "money":              float,
  "tiles":              [[tile, ...], ...],   # tiles[y][x]
  "farmer":             [x, y],
  "hands":              [[x, y], ...],         # hired hands for the current day
  "unlocked_quadrants": ["NW", ...],          # subset of {"NW","NE","SW","SE"}
  "hires_today":        int,                  # used to price the next HIRE
}
```

一个 `tile` 是以下之一：

- `None` — 未解锁的空格
- `"LOCKED"` — 玩家尚未购买的象限中的格子
- 一个植物字典：
  ```py
  {
    "kind":                 "PLANT",
    "crop":                 "WHEAT" | "CARROT" | "TOMATO" | "STRAWBERRY" | "MELON",
    "planted_day":          int,
    "watered_today":        bool,   # reset to False each end-of-day
    "consecutive_unwatered": int,   # 2+ → tile turns to a weed
    "yield_units":          int,    # units currently harvestable
    "max_lifespan_step":    int,    # step at which decay begins; -1 for ongoing crops
    "fertilized_until_day": int,    # last day fertilizer bonus applies; -1 if none
  }
  ```
- 一个杂草字典：`{"kind": "WEED"}`
- 一个动物结构字典（合作社/牧场，可选占用）：
  ```py
  {
    "kind":                 "COOP" | "PASTURE",
    "animal":               "GOOSE" | "COW" | "SHEEP" | None,  # None until PLACEd
    "placed_day":           int,
    "yield_units":          int,
    "fed_today":            bool,
    "consecutive_unfed":    int,    # 2+ → animal escapes
    "cared_today":          bool,
    "fertilizer_available": bool,   # set at end-of-day for every surviving animal; cleared by COLLECT_FERTILIZER
    "pending_care_bonus":   int,    # banked CARE bonus, applied on the next yield tick
  }
  ```

<a id="quick-start"></a>
## 快速入门

```py
from kaggle_environments import make


def my_agent(obs):
    # Buy one wheat seed on the very first turn, then PASS forever after.
    if obs.get("step", 0) == 0:
        return {"farmer": ["PASS"], "market": [["BUY_SEED", "WHEAT", 1]]}
    return {"farmer": ["PASS"], "market": []}


env = make("kaggriculture", configuration={"episodeSteps": 200})
env.run([my_agent, "random"])
env.render(mode="ipython", width=800, height=800)
```

<a id="configuration-defaults"></a>
## 配置默认值

每种作物的种子成本和每种产品的基础价格不可配置；它们在上方的类型和价格函数表中已记录。可配置的参数如下：

|参数|默认值|描述|
| :---- | :---- | :---- |
|episodeSteps| 720 |赛季总回合数（24回合 × 30天）|
|板大小| 10 |每个玩家的方形农场的宽和高（以方格为单位）。高级用法：10 = 四个 5x5 的区域|
|初始资金| 3000 |每个玩家开始时拥有的硬币数量|
|每回合最大市场订单数| 10 |每回合每个玩家处理的最大市场订单数量；超出部分会被静默丢弃|
|每天回合数| 24 |构成一个游戏日的回合数量|
|储藏室容量| 100 |储藏室能容纳的最大非种子物品数量；每日结束时的溢出部分会被丢弃|
|杂草生成概率| 0.005 |每格空闲且未解锁的方格在每日刷新时生成杂草的概率|
|城镇商店解锁间隔| 3 |连续城镇商店解锁之间的天数（有放回抽样，最多8次）|
|城镇商店销售间隔| 4 |每个已解锁城镇商店实例之间消费周期的回合数|
|城镇中心销售间隔| 24 |城镇中心消费周期的回合数（固定速率，每天一次）|
|种子|null|用于确定性场景生成的可选输入种子；读取后会从配置中清除，以确保不会出现在代理观察中|
