# CHI 代理 — `chi.py` 到 `chi10.py`

> 范围：仅原始 CHI 他uristic 规划器血统。公开衍生和 CHI10 之后的实验在 `public_agent.md` 中单独记录。
本文件描述了基于已实现代理的 Kaggriculture 他uristic 规划器的各个版本。

<a id="1-objective"></a>
## 1. 目标

规划器采用增量方法：

1.  定义一个确定性的第 1 天开盘；
2.  将固定计划转换为可重用的路径和操作堆栈；
3.  在第 1 天之后维持作物和动物生产；
4.  动态分配每日任务；
5.  减少移动和不必要的雇佣；
6.  处理用于动物饲料的小麦短缺；
7.  避免不必要的动物护理操作；
8.  调整路线以适应实际工人生成位置；
9.  协调收获和销售时间；
10. 在农场扩展后停止自动重新种植；
11. 清除解锁土地上的杂草；
12. 将土地购买推广至四个象限。

目标是保持代理的确定性和可检查性，同时逐步使其决策依赖于实际农场状态。

<a id="2-initial-prototype-----chipy"></a>
## 2. 初始原型 —— `chi.py`

初始版本直接将第 1 天的开盘定义为操作序列。

<a id="day-1-purchases"></a>
### 第 1 天采购

在第 0 小时：

-   10 粒小麦种子；
-   6 粒胡萝卜种子；
-   2 粒草莓种子；
-   1 只鹅；
-   2 头牛；
-   1 只羊；
-   16 粒小麦；
-   3 名农场工人。

在第 1 小时：

-   1 粒番茄种子；
-   2 粒西瓜种子。

<a id="day-1-layout"></a>
### 第 1 天布局

作物布局包含：

  作物           土地格数
  ------------ -------
  小麦             10 胡萝卜             6 番茄             1 草莓         2 西瓜              2

动物区域占据右下角 2x2 区域：

  位置   动物
  ---------- --------
  `(3, 3)`   鹅 `(4, 3)`   牛 `(3, 4)`   羊 `(4, 4)`   牛

农民构建并初始化动物区域，同时三名农场工人在作物区域进行种植和浇水。

该原型仅执行第 1 天。从第 2 天开始，所有工人均通过。

<a id="3-chi-1-----final-fixed-day-1-opening"></a>
## 3. CHI 1 —— 最终固定的第 1 天开盘

CHI 1 保持相同的农场布局，但将开盘修改为使用四名雇佣农场工人。

<a id="main-changes"></a>
### 主要变更

-   由三名变为四名农场工人；
-   小麦种子在第 1 小时购买；
-   作物区域被划分为四个固定路径；
-   农民仍专注于动物区域的设置。

<a id="fixed-worker-roles"></a>
### 固定工人角色

  工人   角色
  -------- ------------------------------------------------------
  农民   构建动物区块，放置动物，喂养和护理 手 1   右侧作物路径 手 2   左侧作物路径 手 3   内部作物路径 手 4   剩余作物格子的短路径

这成为后续版本重复使用的固定第 1 天开盘。

<a id="4-chi-2-----paths-and-action-stacks"></a>
## 4. CHI 2 —— 路径和操作堆栈

CHI 2 将大型硬编码的动作序列替换为基于路径的表示方式。

第1天的移动路径变为：

``` text
Farmer: W -> N -> E

Hand 1: W -> N -> N -> N -> N -> W -> W -> W -> S

Hand 2: N -> W -> W -> W -> W -> N -> N -> N -> N

Hand 3: W -> N -> W -> N -> N -> N -> W -> S -> W -> S

Hand 4: N -> W -> W
```

不再显式编写路线中的每一个 `PLANT`、`WATER`、`PLACE`、`FEED` 和 `CARE`，规划器会根据工人到达的方格推导出相应动作。

对于作物：

``` text
reach crop tile
    -> PLANT
    -> WATER
```

对于动物：

``` text
reach animal tile
    -> BUILD if required
    -> PLACE
    -> FEED
    -> CARE
```

动作被插入到栈中，并以每tick为单位逐个消耗。

本版本确立了后续规划器所采用的执行模型。

<a id="5-chi-3-----dynamic-multi-day-planner"></a>
## 5. CHI 3 --- 动态多日规划器

CHI 3 将代理的范围扩展到第1天之后。

<a id="persistent-farm-state"></a>
### 持久农场状态

规划器为每个作物和动物方格引入了明确的状态。

作物状态跟踪：

-   作物类型；
-   是否已播种；
-   是否已准备收获。

动物状态跟踪：

-   动物类型；
-   是否已放置；
-   可提供的产量；
-   可提供的肥料。

状态每tick从观察结果中刷新一次。

<a id="crop-production"></a>
### 作物产量

规划器区分一次性作物和持续性作物。

  作物　类型　收获日龄
  ------------ ---------- ----------------
  小麦：一次性，4；胡萝卜：一次性，3；番茄：持续产出，8、9、10、11；草莓：持续产出，10、12、14、16；Melon：一次性，10。

当前可能的作物任务现在包括：

``` text
WATER
HARVEST
REPLANT
```

一次性作物重新播种所需的种子将自动购买。

<a id="animal-production"></a>
### 动物产量

动物任务可以包括：

``` text
BUILD
PLACE
FEED
CARE
COLLECT_FERTILIZER
HARVEST
```

<a id="dynamic-daily-routing"></a>
### 动态每日路径规划

在第1天之后，规划器：

1.  创建作物和动物任务；
2.  估算其动作成本；
3.  将其分配给可用工人；
4.  将邻近任务合并排序；
5.  将任务坐标转换为移动路径；
6.  搜索能够以工人容量完成工作的最少雇佣数量。

这是首次实现每日路径和雇佣动态计算的版本。

<a id="6-chi-4-----dedicated-livestock-block"></a>
## 6. CHI 4 — 专用畜牧任务块

CHI 4 调整任务分配，将全部动物任务集中交给同一名工人。

此前，动物任务可以由通用分配器分布在不同工人之间。

新规划器：

1.  构建完整的动物路径；
2.  测试哪个工人能够执行该路径；
3.  将畜牧区块分配给最便宜的可行工人；
4.  在剩余可用容量上分配作物任务。

先保持动物路线连续，再向该工人追加作物任务。

<a id="purpose"></a>
### 目的

这减少了紧凑的 2×2 畜牧区域周围的任务碎片，使动物管理更可预测。

<a id="7-chi-5-----wheat-shortage-and-animal-sequencing"></a>
## 7. CHI 5 — 小麦短缺与动物任务排序

CHI 5 处理储藏室中没有足够小麦喂养全部动物的情况。

规划器现在有两种模式。

<a id="normal-mode"></a>
### 正常模式

使用场景：

``` text
shed Wheat >= number of animals
```

使用常规的专用动物路线。

<a id="wheat-shortage-mode"></a>
### 小麦短缺模式

当小麦不足时，动物工作流程会被拆分为独立的任务类型：

``` text
ANIMAL_PRE
WHEAT_SUPPLY
SHED_DROP
WAIT_WHEAT
ANIMAL_FEED
REPLANT_WHEAT
```

一名供应商工人：

1.  前往成熟的小麦区域；
2.  浇水并收获所需的小麦；
3.  返回中心；
4.  将小麦放入储藏室。

一名饲喂工人：

1.  抵达中心；
2.  等待足够小麦可用；
3.  领取小麦；
4.  沿动物喂养路线前进。

不需要小麦的动物工作可以通过`ANIMAL_PRE`独立完成。

动物操作顺序也已更改，确保在新的喂养/护理周期开始前先收集可用的生产资源和肥料：

``` text
HARVEST if available
COLLECT_FERTILIZER if available
FEED
CARE
```

本版本解决了作物生产与动物喂养之间的依赖关系，而不是将每个动物任务视为立即可执行。

<a id="8-chi-6-----hiring-and-shortage-route-optimization"></a>
## 8. CHI 6 --- 用工与短缺路线优化

CHI 6 对 CHI 5 引入的短缺规划器进行了改进。

主要目标是避免仅仅因为一名工人在等待小麦而就额外雇佣工人。

<a id="tick-aware-planning"></a>
### 时钟感知规划

规划器引入了：

``` text
DAY_TICKS = 24
```

并明确考虑了新雇佣农场工人存在的一tick启动延迟。

供应商/喂养者配对是根据以下时间点选择的：

-   供应商可以停止供应小麦；
-   喂养者可以到达棚舍；
-   完整的喂养路线可以完成。

<a id="use-waiting-time-productively"></a>
### 有效利用等待时间

喂养者不再被迫等待小麦到达而空闲。

在`WAIT_WHEAT`之前，规划器尝试插入那些在供应商到达棚舍前仍可完成的任务。

优先处理`ANIMAL_PRE`任务。

供应商还可以执行：

-   收获后的小麦重新种植；
-   如果仍有容量，执行附近的额外任务。

<a id="result"></a>
### 结果

工人容量被更高效地利用，使规划器可以从零雇佣开始向上搜索，并保持最小的有效工作团队。

<a id="9-chi-7-----care-optimization"></a>
## 9. CHI 7 --- 照顾优化

CHI 7 增加了对动物生产容量的认知。

规划器现在追踪：

``` text
pending_care_bonus
```

每只动物的状况。

最大持有产量表示为：

  动物     最大持有产量
  -------- -------------------------
  鹅                            4 牛                              6 羊                            6

CARE不再自动添加到每只动物的访问中。

实施的条件是：

``` text
pending_care_bonus + 1 < animal maximum held production
```

如果该条件为假，则省略CARE操作。

该条件同时用于：

-   常规动物行为；
-   `ANIMAL_PRE`短缺任务。

路线成本估算器仅在实际需要时才包含CARE，因此招聘和路线选择都受益于工作量的减少。

<a id="10-chi-8-----sale-expansion-and-land-management"></a>
## 10. CHI 8 --- 销售、扩展和土地管理

CHI 8 将规划器从生产维护扩展到农场扩展，并迈向一种未来动态地块分配策略。

<a id="real-worker-positions"></a>
### 实际工人位置

每日规划最初根据已知的棚屋入口生成模式来估算工人的起始位置。

在第1小时，一旦在观察中可见雇佣工人，其实际位置将被存储，并从这些坐标重新构建路线。

这避免了因假设所有工人均从同一棚屋入口开始而引起的路线成本错误。

<a id="sale-day-planning"></a>
### 销售日规划

定义一个专门的销售日为：

``` text
SALE_DAY = 5
SALE_DROP_HOUR = 22
SALE_HOUR = 23
```

在该日，工人的容量和路线成本需考虑返回棚屋以进行销售的行程。

工人会返回棚屋入口区域并在市场销售前放下其库存。

在销售日达到2龄的胡萝卜将提前收获：

``` text
WATER
HARVEST
```

它们不会被重新种植。

<a id="expansion-mode"></a>
### 扩展模式

一旦解锁超过初始`NW`象限，扩展模式即被激活：

``` text
EXPANSION_ACTIVE = len(unlocked_quadrants) > 1
```

扩展之前，原有的重新种植策略将被保留。

扩展之后：

-   现有作物将继续被灌溉；
-   成熟作物将继续被收获；
-   一次性作物在收获后不再重新种植；
-   不再购买替换种子；
-   空出的收获地块将被作物规划器忽略。

这为CHI 9计划的动态地块评分策略留下了空出地块。

<a id="weed-tasks"></a>
### 除草任务

规划器会扫描整个农场网格以检测可见的杂草。

每个检测到的杂草都可以生成一个明确的任务：

``` text
WEED
    -> DIG
```

因此，即使杂草不在原始作物位置上，它们也会被包含在路线分配中。

扩展之后，移除杂草不会触发自动重新种植。

<a id="generalized-land-purchases"></a>
### 通用土地购买

土地价格被明确表示为：

``` text
1 -> 1000
2 -> 2000
3 -> 4000
```

其中键是已解锁的象限数量。

因此，下一土地成本为：

    Quadrants already unlocked        Next land cost
  ---------------------------- ---------------------
                             1                  1000
                             2                  2000
                             3                  4000

规划器使用专用函数来确定下一价格以及当前可用现金是否足够。

这消除了之前专门与第二个`NE`象限相关的逻辑，并允许相同的购买机制处理第二、第三和第四象限。


<a id="11-chi-9-----dynamic-production-labor-and-endgame-optimization"></a>
## 11. CHI 9 --- 动态生产、劳动力和终局优化

CHI 9 在启发式规划器中增加了更动态的经济和终局策略。

<a id="dynamic-worker-count-calculation"></a>
### 动态工人数量计算

雇佣农场工人的数量不再仅基于每日任务集是否在工人容量范围内。

规划器首先搜索最小有效劳动力配置，然后检查雇佣一名额外工人所带来的额外预期产量是否足以抵消下一次雇佣的成本。

额外雇佣停止的条件是：

``` text
additional expected profit < next hire cost
```

这使得规划器能够在不造成劳动力不足的同时，避免雇佣不必要的工人，当额外产能无法自我偿还时即停止。

<a id="conditional-crop-watering"></a>
### 作物条件灌溉

作物不再每天自动进行灌溉。

规划器追踪：

``` text
watered_today
consecutive_unwatered
needs_water
```

仅在作物生存需要灌溉或收获前仍需灌溉时，才会创建WATER操作。

这消除了不必要的WATER操作，并降低了每日路线成本。

<a id="endgame-planting-constraints"></a>
### 终局种植约束

种植和重新种植决策现在结合作物生产计划和当前日期进行判断。

只有当作物的首次收获仍能在最后可用收获日之前完成时，才会进行种植：

``` text
planting day + first harvest age <= last harvest day
```

同样的原则也适用于新动物，使用其首次生产年龄作为判断标准。

因此，无法在最终销售前完成收获的生产将被排除在以下内容之外：

-   新种植；
-   重新种植；
-   动物安置；
-   生产评分；
-   市场采购订单。

<a id="dynamic-production-purchasing"></a>
### 动态生产采购

此前固定的开市后生产策略被一个预算感知的生产选择系统所取代。

对于可用或即将空置的地块，规划器会评估可能的作物和动物，使用：

-   预期边际市场收入；
-   生产采购成本；
-   预期动物饲料成本；
-   额外人工成本；
-   地块占用时间；
-   有效空间利用率。

候选方案根据每单位有效占用空间和时间的边际利润进行评分。

仅保留正向且可负担的生产选择。

最终计划将被转换为种子、动物和小麦所需的市场订单。

<a id="land-purchase-profitability"></a>
### 土地购置盈利能力

土地扩张也通过预期产量进行评估。

在购买新区域之前，规划器会估算：

-   可在新土地上安装的产量；
-   预期边际利润；
-   由此产生的工人需求；
-   种子、动物和饲料成本；
-   额外雇佣成本。

只有当预期产量仍可负担且相对于土地价格足够盈利时，才会保留该购买决策。

费用为 4000 的最终扩地操作在第 19 天后也会禁用。

<a id="continuous-sales"></a>
### 持续销售

从第6天起，收获的非小麦产品可以直接从棚屋出售，而无需等待后续的集中清算。

每日销售集合包括：

``` text
CARROT
TOMATO
STRAWBERRY
MELON
EGG
MILK
WOOL
```

肥料仍可独立出售。

<a id="final-liquidation"></a>
### 最终清算

第29天，工人开始向棚屋入口中心返回，以在最终市场清算前完成可售产品的提交。

从第22小时开始，棚屋内剩余的所有可售产品均被提交至市场：

``` text
SELL all remaining market products
```

这确保了比赛末期仍保留在棚屋中的产品能在比赛结束前转化为现金。



<a id="additional-retained-improvements"></a>
### 额外保留的改进

主要新增内容被有意限制为：

- 事件和市场感知的生产估值；
- CARE感知的动物生产估算；
- 棚屋溢出保护机制；
- 针对价格敏感产品的计量销售机制；
- 基于四个有效棚屋入口格子的最近棚屋物流方案；
- 不设人工10手上限的扩展斐波那契雇佣成本；
- 当格子生产类型发生变化时，更安全的生产状态同步机制。

这些变更保留了原有的贪婪路径分配器，同时提升了经济模型和执行鲁棒性。


<a id="12-chi-10-----observation-checked-execution-and-cash-flow-planning"></a>
## 12. CHI 10 --- 观察验证的执行与现金流规划

CHI 10 保留了 CHI 9 的规划结构，并专注于使执行和经济估算更贴近真实游戏状态。

主要新增内容包括：

- 基于事件的自身及对手公开供应预测；
- 针对预测销售的单位市场价格模拟；
- 具有现金流感知的生产与雇佣决策；
- 在执行前，对队列中的工人操作进行与当前观察结果的验证；
- 自适应的销售与棚屋容量处理，包括当前回合期间已存入的产品；
- 更紧致的终局路径规划与清算处理。

CHI 10 保留了相同的贪婪路径架构，同时提升了执行验证和经济规划能力。

<a id="chi-10-temporal--experimental-rolling-horizon-scheduler"></a>
### CHI 10 时间维度 —— 实验性滚动时域调度器

`src/agents/chi10_temporal.py` 是一个独立变体，采用 CHI 10 的开局和经济模型。在开局之后，它会从每一时刻观察到的工人位置、格子和库存中重新构建一个时间调度方案。

调度器最多保留四个替代方案（每日雇佣估算期间保留两个）。它可以跳过一个可选任务，以保留时间用于更优的任务链。任务按照固定优先级顺序处理，且该顺序与优先级兼容，这是一种有界启发式算法，而非全局最优求解器。

该调度方案考虑了：

- 每个工人每时刻仅执行一个动作或移动；
- 收获前需浇水，种植后必须浇水；
- 共享种子预留、动物取货和小麦供应情况；
- 不同工人的小麦收获/存入/取货依赖关系；
- 雇佣工人和购买资源在下一时刻变为可用；
- 在时间范围结束前的返回行程和存入操作。

每日购买估算假设所需物资可以购买。实时执行仅使用观察到的库存，按工人顺序检查操作，将存款限制在可用的棚屋空间内，并在销售中包含同回合转移。购买失败或意外状态变化通过重新规划处理。棚屋拥堵和未来销售价格在搜索中仍为近似值。

在默认的720步游戏中，最后一个可执行的观察是在第29天，第22小时。最终计划为在该操作结束前预留时间进行存款；无法依赖每日结束时的自动存款来完成最后销售。

已从本变体中移除未使用的贪婪路由、排队执行、旧销售设置和过时的生产估算辅助工具。该代理仅使用Python标准库，并支持默认的游戏设置。

从仓库根目录运行聚焦测试：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_chi10_temporal.py -q -p no:cacheprovider
```

完整游戏检查为可选功能。它们在两个玩家位置上使用两个种子对CHI 10进行测试，验证完成情况，并使用真实引擎检查工人的操作。JUnit输出记录奖励和最大测量操作时间：

```powershell
$env:RUN_KAGGRICULTURE = "1"
.\.venv\Scripts\python.exe -m pytest tests/test_chi10_temporal.py -q -p no:cacheprovider -o junit_family=xunit1 --junitxml=experiments/chi10_temporal_validation.xml
Remove-Item Env:RUN_KAGGRICULTURE
```

这些检查覆盖了测试场景中的执行情况；它们并未证明相对于CHI 10的竞争性改进。
