<a id="main-idea"></a>
## 核心思想

不要因为当前地块看起来已满就购买土地。仅当在现有土地上无法容纳额外的盈利性生产，且存在一个具体的开发计划证明购买后在土地成本、劳动力、物流、维护以及游戏结束约束条件下仍保持可行和盈利时，才应购买土地。

`v2` 完整继承了 [`v1`](heuristic_ideas_v1.zh-CN.md)。仅本文件中添加、替换和修正的内容会改变继承的设计。

<a id="core-ideas-added-in-v2"></a>
## v2 中新增的核心思想

<a id="1-separate-land-purchase-from-placement"></a>
### 1. 将土地购买与地块放置分离

`CHOOSE_PLACEMENTS()` 仅应在已有地块上进行生产放置。

它不再自行决定在未找到地块时购买土地。土地扩张应成为在日常任务生成之前明确的战略决策。

这可以避免将局部放置失败转化为自动且昂贵的购买行为。

<a id="2-compare-expansion-against-a-no-purchase-baseline"></a>
### 2. 将扩张与不购买的基准进行对比

在考虑新增土地之前，应构建一个仅使用当前可解锁地块的最佳方案。

该基准应包含：

- 免费地块；
- 有价值的挖掘；
- 兼容的空置结构；
- 收获或生命周期结束后将变为免费的地块；
- 游戏结束前可行的旋转方案；
- 必要的雇佣；
- 维护；
- 可实现的销售。

只有在该基准中仍盈利但无法容纳的生产，才构成真实的土地需求。

<a id="3-a-full-field-is-not-enough-to-justify-buy_land"></a>
### 3. 仅当存在明确的生产容量问题时，才应触发 `BUY_LAND`

明确拒绝两种反模式：

- 地块视觉上已满，并不证明需要更多土地；
- 工人短缺，并不证明土地短缺。

扩张应解决的是生产容量问题，而非掩盖路线或劳动力问题。

<a id="4-reserve-a-concrete-exploitation-plan-before-purchase"></a>
### 4. 在购买前必须预留一个具体的开发计划

对于下一个合法区域，应在复制的状态上模拟购买，并明确新地块将如何实际被使用。

该模拟计划必须包含：

- 未来的具体生产；
- 种子或动物；
- 安装时间；
- 未来的维护；
- 必要的雇佣；
- 运输与行进路线；
- 游戏结束前预期的销售；
- 完整的土地成本。

该购买仅在该计划可行且相较于维持现有土地能产生正净收益时才有效。

<a id="5-validate-cash-labor-routing-and-deadlines-together"></a>
### 5. 一起验证现金、劳动力、路径和截止日期

仅凭看似有利可图的作物清单是不够的。

当出现以下情况时，必须拒绝扩张：

- 安装发生过晚；
- 无法进行维护服务；
- 现金变得不足；
- 劳动力容量不足；
- 路径无法匹配；
- 预期收益无法覆盖土地成本。

这将使 `BUY_LAND` 从一个投机性购买转变为一个完全规划的承诺。

<a id="6-do-not-place-production-on-unconfirmed-land"></a>
### 6. 不要在未经确认的土地上安排生产

依赖于待定 `BUY_LAND` 的生产仅是一种预留。

在购买被确认之前，不得实际安排任何生产或路径指向 `LOCKED` 格子。

如果当前可用土地上不存在有效的生产布局，应推迟或取消该生产，而不是假装未来土地已经存在。

<a id="7-confirm-expansion-from-observations-not-assumptions"></a>
### 7. 从观察结果中确认扩张，而非基于假设

只有当新解锁的格子出现在观察状态中时，土地购买才被视为真实。

确认之后：

- 检测到新的格子；
- 记录实际成本；
- 重新验证预留的开发计划；
- 移除其假设不再成立的使用项；
- 立即将新格子整合进正常规划中。

如果购买未被确认，则删除相关预留并重新规划。

<a id="8-treat-sunk-land-cost-correctly"></a>
### 8. 正确处理已沉没的土地成本

在购买确认后，不得仅为了抵消已支出的土地费用而保留一个无利可图的生产计划。

最初的购买决策与购买后的最佳决策是两个独立的问题。一旦成本已沉没，未来的生产仍应基于其剩余价值进行评估。

<a id="9-buy_land-is-a-real-market-dependency"></a>
### 9. `BUY_LAND` 是一个真实的市场依赖关系

`BUY_LAND` 占用 10 个市场订单槽位中的一个，不得与其他订单合并。

在发送前需验证：

- 现金安全储备；
- 前提条件；
- 依赖的生产计划。

如果 `BUY_LAND`、另一个 `BUY` 或一个 `HIRE` 被延迟或移除，所有依赖的计划都必须重新验证。

<a id="10-reevaluate-land-only-when-its-assumptions-matter"></a>
### 10. 仅当其假设具有实际意义时才重新评估土地

土地评估无需每一步都盲目运行。

当经济变化或布局要求改变了当初支持或拒绝扩张的条件时，应重新计算。

<a id="key-invariants"></a>
## 关键不变量

- 不存在因布局失败而隐含的 `BUY_LAND`。
- 没有具体日期的开发计划，不得进行购买。
- 除非能优于无土地的最佳方案，否则不得进行购买。
- 任何生产操作均不得针对锁定的格子。
- 土地成本、种子/动物、雇佣、维护、路径以及可实现的销售都必须全部包含在内。
- 一个待定购买不被视为已确认的容量。
- 一个已确认但现已不盈利的用途即使土地成本已经发生沉没成本，也可能被取消。
- `BUY_LAND` 消耗一个市场槽位，并像其他购买一样传播依赖关系。

<a id="what-v2-changes-relative-to-v1"></a>
## 与 v1 相比，v2 的变更是什么

`v2` 保留了 `v1` 的每日计划器，但将土地扩张作为一个独立的、计划中的经济决策。主要改进是用模拟的、预留的、并经观察确认的扩张来替代反应式的扩张。
